# Double Dribble Native-Port Rules

These instructions apply to every contributor and agent working in this repository.

## Non-negotiable architecture

- This is a native C port, not an emulator, compatibility layer, instruction interpreter, ROM-call wrapper, or recorded-log player.
- Convert observed 6502 routines into named C state machines, algorithms, and data structures. Preserve behavior, not CPU machinery.
- The shipping runtime must load only a generated `.assetpack`. It must never open, map, scan, or execute the NES ROM.
- Mapper 2/UxROM bank selection is an importer and reverse-engineering concern only. Runtime code must use stable asset-pack entry identifiers and native structures.
- Do not commit a ROM, PRG/CHR dump, decoded graphics, DMC sample, screenshot from the original game, save state, movie, or any other copyrighted binary asset. The sole exception is the user-supplied application icon at `resources/double_dribble.ico`; it is branding metadata and is never loaded as game content.
- Build/capture/Ghidra outputs stay under ignored local directories (`build/`, `captures/`, or `ghidra-projects/`).

## Required evidence workflow

1. Establish original behavior in FCEUX. Use a checked-in Lua script when memory, PPU, APU, mapper, or instruction observations are needed.
2. Capture an original screenshot at a named frame or state under ignored `captures/original/`.
3. Trace the responsible code in Ghidra. Prefer live Ghidra MCP queries; use the checked-in headless scripts when the MCP server is unavailable.
4. Record CPU address, active UxROM bank, ROM file offset, inputs, outputs, and confidence in `PORTING.md` or a focused document.
5. Implement the behavior as native C and extract only the required data into the asset pack.
6. Capture the native frame under ignored `captures/native/` and compare it against the reference at the NES logical resolution of 256 x 240.

Do not infer a ROM offset from a CPU address without recording the active bank. For this Rev 1 ROM, `$C000-$FFFF` is fixed to the final 16 KiB PRG bank and `$8000-$BFFF` is mapper-selected.

## Asset-pack contract

- `--build-assetpack <rom.nes> <output.assetpack>` is the only supported asset import path.
- Validate the iNES header, mapper, PRG size, and an allow-listed ROM identity before extracting anything.
- Every entry records a type/version, stable name or ID, size, checksum, and source provenance.
- Parsers fail closed on truncation, duplicate entries, checksum mismatch, wrong ROM revision, or unsupported entry versions.
- Tests may use synthetic fixtures generated by source code. They may not add real game bytes to the repository.

## Coding and build standards

- Target C17. Public headers belong in `include/`; implementation belongs in `src/`; reverse-engineering helpers belong in `tools/`.
- Keep platform, rendering, audio, asset parsing, and scene logic in separate modules.
- Keep warnings enabled and fix new warnings. All sizes and file offsets require overflow and bounds checks.
- Normal launch requires an explicit or discoverable `.assetpack`; missing assets are a clear startup error, never a fallback to the ROM.
- Preserve original 60 Hz state timing. Rendering may scale, but fidelity captures use nearest-neighbor 256 x 240 output.
